# CLAUDE.md

## Project Overview

`dark-mode-toggle` is a lightweight, zero-dependency custom HTML element (`<dark-mode-toggle>`) that provides an accessible dark/light mode toggle with localStorage persistence, cross-tab sync, and OS preference detection.

## Architecture

- **Single-file component**: All logic lives in `dark-mode-toggle.js` as a native Custom Element using Shadow DOM.
- **No build step required** for development; the minified file in `docs/` is generated by CI for the demo page.
- **Two theming strategies**: `data-theme` attribute on a root element, or CSS class toggling (e.g., Tailwind's `dark` class).
- **Sync mechanisms**: `BroadcastChannel` for cross-tab sync, `storage` events as fallback, `prefers-color-scheme` media query for OS preference.

## Development Conventions

- **Edit only `dark-mode-toggle.js`**; the minified file is generated automatically by CI (Terser via `npx`).
- The component is a single class extending `HTMLElement`; keep it dependency-free.
- Attribute names use kebab-case (`dark-class`, `data-theme`, etc.) per HTML conventions.
- Internal methods use underscore prefix (`_applyFromExternal`, `_reflectFromRoot`, etc.) to distinguish from public API.
- `disconnectedCallback` must disconnect any `MutationObserver` instances and close the `BroadcastChannel` to prevent memory leaks.

## Common Tasks

**Run the demo locally**
Serve `docs/index.html` with any static file server:
```bash
npx serve docs/
# or
python3 -m http.server --directory docs 8080
```

**Minify manually** (if not waiting for CI):
```bash
npx terser dark-mode-toggle.js -o docs/dark-mode-toggle.min.js --compress --mangle
```

**Trigger CI minification**: Push to `main` or manually dispatch the workflow from the GitHub Actions tab.

## What to Avoid

- **Do not edit `docs/dark-mode-toggle.min.js` by hand** — it is overwritten by CI on every push to `main`.
- **Do not introduce dependencies** — the component is intentionally zero-dep; keep it that way.
- **Do not pass unsanitized user input to `document.querySelector()`** via the `root` attribute — validate that the selector is a simple `#id`, `.class`, or element name before use.
- **Always wrap `localStorage` access in try/catch** — private browsing and strict browser policies throw `SecurityError` on storage access; fail silently with a graceful fallback to avoid breaking the component entirely.
- **Validate external inputs** (`localStorage`, `BroadcastChannel` messages) against an explicit allowlist (`['light', 'dark', 'auto']`) before applying theme state — do not trust arbitrary values from external sources.
- **Avoid double attribute mutations** — prefer a single `setAttribute` call over `toggleAttribute` + `setAttribute` pairs that trigger two MutationObserver callbacks per state change.
- **Do not add FOUC mitigation inside the component** — the pre-paint inline script must be placed in `<head>` by the consumer; see `docs/index.html` for a reference implementation.
- **Do not pin actions by mutable tag** (e.g., `@v5`) in CI without a commit SHA — use a specific SHA to prevent supply chain attacks from tag reassignment.
